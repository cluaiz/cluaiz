## Method

- Prompt: about 544 tokens of plain text, a new random number in front each run (no KV prefix reuse).
- Generation: `max_tokens` 64. Runs per model and mode: 3.
- Run 1 is the cold run (first request after load, thinking on `auto`, also checks for leaked control tokens). Later runs use thinking `off`, so exactly `max_tokens` are generated; speeds are the average of those warm runs.
- `temporary_chat: strict` (no memory / RAG). Modes: `auto` = planner decides; `gpu` = `n_gpu_layers -1`; `split` = half the blocks on the GPU; `cpu` = `n_gpu_layers 0`.
- llama-bench gets the placement the engine reported (`-ngl`, `-ncmoe`, KV type, flash attention, op offload, threads, batch, ubatch, mmap). Prompt speed is measured from an empty context, generation after the same number of prompt tokens (`-d`), like the engine run.
- A gap is flagged when engine generation < 0.85 x llama.cpp.
