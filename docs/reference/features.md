# Engine Features

Every feature of the Cluaiz Engine (the `cluaiz` program in this repository) on one page: what it does,
when you need it, one example, its status, where the code is and which test run checked it. The App and
the tools registry have their own docs.

## How to read this page

- **Status**: `release` = in v0.1.0 (2026-11-16). `main` = added after v0.1.0 on the `main` branch, not in
  a release package yet; planned for the next release (0.2.0). `source only` = in the code but not in the
  release packages; you build it yourself. A row with two parts (for example "release; X: main") had the
  feature in v0.1.0 and the named part added later.
- **Source**: the file or folder where the feature lives.
- **Proof**: the test run in [`test/cloud/runs/`](../../test/benchmarks/README.md) that checked it; each link opens
  the run's folder with its summary and raw results. `?` means no run record yet (some of these have unit
  tests only).
- A linked feature name opens its detailed docs page.
- **Examples**: replace `<model>` with an installed id from `cluaiz list`. HTTP examples show the route and
  the JSON fields that matter. CEP examples show the method and its `params`, sent like this:

```bash
curl http://127.0.0.1:8000/v1/cep \
  -H "Authorization: Bearer $(cat ~/.cluaiz/session.token)" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc": "2.0", "id": 1, "method": "kv.status", "params": {}}'
```

The host and port come from `permission.json` (8000 is the default port). The token header is needed when
API auth is on (`api_auth.required`).
